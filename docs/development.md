# 开发规范

## 环境基线

- Node.js：`>=20.9.0`
- 包管理器：npm，依赖以 `package-lock.json` 为准
- 应用框架：Next.js 16、React 19、TypeScript strict mode
- 测试运行器：Node.js test runner，通过 `tsx` 加载 TypeScript

首次安装使用 `npm ci`，不要用会隐式改写锁文件的安装方式替代可复现安装。

## 目录职责

| 目录 | 允许内容 | 不应放入 |
| --- | --- | --- |
| `src/app` | 页面、布局、Route Handlers、路由样式 | 设备协议和持久化实现 |
| `src/components` | 客户端 UI 与交互状态 | 服务端凭据、文件系统访问 |
| `src/lib` | 领域逻辑、集成适配器、状态聚合 | 页面专用样式 |
| `src/types` | 跨模块数据契约和第三方声明 | 运行时副作用 |
| `tests` | 可重复、无真实设备依赖的测试 | 生产数据和密钥 |
| `hardware` | 固件、边缘采集脚本、接线说明 | Web 应用业务代码 |
| `deploy` | 服务与反向代理部署配置 | 构建产物和服务器凭据 |
| `scripts` | 构建、打包、发布自动化 | 运行时业务逻辑 |
| `docs` | 架构、洞察、开发与产品资料 | 生成报告和临时草稿 |

## 本地工作流

```bash
npm ci
cp .env.example .env.local
npm run dev
```

提交前必须运行：

```bash
npm run check
```

`check` 依次执行静态检查、单元测试、类型检查和生产构建。修改硬件固件或部署脚本时，
还需要在对应目标环境完成编译或配置校验；当前主项目命令不会编译 Arduino 固件，也
不会启动 Nginx 或 systemd。

## 配置与秘密

1. 真实密码、token、session、服务器私钥和设备清单不得提交。
2. 新增环境变量时同步更新 `.env.example` 和相关文档，示例值必须不可用。
3. 浏览器可见变量才允许使用 `NEXT_PUBLIC_`；MQTT 和 Home Assistant 凭据必须留在服务端。
4. 运行时 JSON 只写入 `PIT_CONFIG_DIR`，不得写入源码目录。
5. 新增外部服务地址时优先通过环境变量注入，并明确超时、重试和 TLS 要求。

## 代码边界

- `PitHub` 是当前设备影子状态的唯一聚合入口；新的 MQTT topic 或 HA 实体投影应完成长度、
  类型、枚举和数值范围校验。
- `ToolManager` 是工具借还状态的唯一所有者；ESP32 只应用 LED 快照，不能反向覆盖
  工具事务。
- 所有改变设备或配置的 Route Handler 必须校验来源、限制请求体大小并返回统一
  `{ ok, data | error }` 结构。
- 客户端实时状态优先走 SSE，轮询只作为降级路径。
- `PitViewport` 通过纯布局模型处理窗口变化；可完整展示时使用居中适配，空间不足时
  保持最低可读比例并允许双向滚动。新增断点必须同步补充模型单元测试。
- 涉及电源的功能必须保留离线判定、数据新鲜度判断和硬件保护，软件不能成为唯一
  安全屏障。
- HA 映射通道不得同时接受 MQTT 电源控制；观察模式必须保持只读，禁止静默回退。

## 文件与提交卫生

- 使用小写、连字符或生态约定的文件名，避免在仓库根目录放置临时文档。
- 生成目录、运行时数据、日志、压缩包和编辑器配置由 `.gitignore` 管理。
- 二进制资源必须有明确运行时用途；当前 `public/wasm/` 是 STEP 导入器的必要依赖。
- 目录移动后同步检查 README、部署脚本、Windows 批处理和打包配置中的相对路径。
- 一次提交只表达一个完整意图，并在提交说明中包含验证结果。
