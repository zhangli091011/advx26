# Home Assistant 迁移方案

## 目标与边界

PIT-OS 使用 `http://192.168.66.34:8123` 作为 Home Assistant 接口基址。
`http://192.168.66.34:8123/home/areas-ting_zi` 是人工访问面板，只用于提示“亭子”
区域；程序通过 HA 注册表解析真实区域 ID。

第一阶段迁移 CH1–CH8 电源开关与功率、电压、电流数据。MQTT 继续服务 ESP32、CAN、
工具柜和视觉扫码。已映射到 HA 的通道以 HA 为唯一权威来源，不允许 MQTT 同时控制。

迁移完成的定义不是“能在 HA 中看见设备”，而是设备不再依赖米家账号、Xiaomi 云、
米家局域网 token 或 Session Broker。推荐 ESPHome、MQTT、ZHA、Zigbee2MQTT 和 Matter。

保留原硬件的条件：

1. HA 实体平台不依赖 Xiaomi/Mi Home 云。
2. 断开互联网后仍能读取状态和控制。
3. 控制和测量实体在重启后保持稳定的 `entity_id`。
4. 继电器额定值、保护和默认状态满足现场安全要求。

不满足条件时应刷写本地固件或更换硬件。

## 准备 Home Assistant

1. 将自定义硬件接入 HA，并为设备分配真实“亭子”区域。
2. 创建 PIT-OS 专用、非管理员用户，只授予所需设备权限。
3. 在该用户资料的安全页面创建长期访问令牌。
4. 令牌只录入 PIT-OS 设置页或 `HOME_ASSISTANT_ACCESS_TOKEN`，不得写入本文件、聊天、
   Git、日志或截图。
5. 在 HA 中确认每个控制实体状态为 `on/off`，测量实体有正确单位。

项目支持 W/kW、V/mV、A/mA。`unknown`、`unavailable`、非法数值或不支持的单位都会
投影为空值，不沿用旧读数。

## 配置 PIT-OS

1. 打开 `/pit/settings`。
2. 在设置页核对本机内网 IPv4；将 HA IP/主机填写为 `192.168.66.34`、端口填写为
   `8123`，模式保持“观察”。
3. 保存长期令牌，重启旁路实例。
4. 执行连接测试，记录 HA 版本和延迟。
5. 点击“发现区域与实体”，确认默认筛选的是 HA 注册表中的真实亭子区域。
6. 依次将 `switch.*` 或 `light.*` 映射到 CH1–CH8。
7. 检查自动建议的功率、电压、电流传感器，必要时显式调整。
8. 保存配置版本 2。

如果运行时仍是版本 1，设置页只读取 MQTT 和旧通道名称作为迁移提示；米家账号、
token、DID 和云 session 不会复制进版本 2。

安全规则：

- 修改 HA 基址时必须重新输入令牌。
- `HOME_ASSISTANT_ACCESS_TOKEN` 托管令牌时，设置页禁止修改基址。
- 同一个控制实体不能绑定多个通道。
- 活动模式至少需要一个有效映射和令牌。
- HA 离线时不回退到同名 MQTT 通道。

## 旁路验证

在生产实例继续运行时，使用独立配置目录和端口 3001 启动旁路实例：

```bash
PIT_CONFIG_DIR=/var/lib/pit-os-ha-preview npm run dev -- --hostname 0.0.0.0 --port 3001
```

旁路配置必须为 `observe`。验证至少持续 30 分钟：

1. 所有映射通道均能显示 HA 的开关状态。
2. 测量数据与 HA 界面一致，单位换算正确。
3. 停止和恢复 HA 网络后，PIT-OS 先显示离线，恢复后自动同步。
4. HA 重启后 WebSocket 自动重连，无需重新保存配置。
5. 旁路实例对电源控制请求返回 409，不向设备发送服务调用。
6. 未映射 MQTT 设备、CAN、工具柜和视觉扫码不受影响。

观察通过后，由现场负责人明确指定一个非关键通道：

1. 临时将旁路配置切为 `active` 并重启。
2. 执行一次开启和一次关闭。
3. 每次操作后 HA 与 PIT-OS 状态应在 5 秒内一致。
4. 测试完成后恢复该负载原始状态。

## 正式切换

1. 停止生产实例，保存上一部署产物。
2. 将原 `pit-config.json` 复制到部署主机私有备份目录，权限设为 `0600`；不得进入仓库。
3. 原子替换为已验证的版本 2 配置和新构建。
4. 启动生产实例，确认 HA 连接、SSE、MQTT 和全部映射通道。
5. 确认不存在第二个仍能控制同一负载的 PIT-OS 实例。
6. 保留上一部署产物和配置备份 24 小时。
7. 稳定 24 小时后删除备份以及所有米家账号、token、DID、session 和旧服务凭据。

代码仓库已移除 MIoT 管理器、米家发现、云客户端、Session Broker 部署和
`homebridge-miot` 依赖。

## 回退

在 24 小时观察期内出现以下任一情况应回退：

- HA 连续离线且现场网络无法及时恢复。
- 实体 ID 不稳定或设备重启后映射丢失。
- 控制服务成功但物理状态未在 5 秒内确认。
- 测量单位或数值与独立仪表明显不符。
- MQTT 非电源功能受到迁移影响。

回退步骤：

1. 停止新生产实例，避免双重控制。
2. 恢复上一部署产物和私有配置备份。
3. 启动旧实例并核对全部关键负载。
4. 记录故障时间、通道、实体、HA 日志和 PIT-OS 日志。
5. 修复后重新从观察模式开始，不直接再次启用活动模式。

24 小时稳定期结束并销毁旧凭据后，回退只允许使用重新配置的本地硬件方案，不再恢复
米家云链路。

## 验收标准

- [ ] 全部已映射控制实体来自本地协议，不依赖 Xiaomi/Mi Home 云。
- [ ] 观察模式连续运行至少 30 分钟。
- [ ] HA 断线与重启测试通过。
- [ ] 非关键负载开、关各一次，状态在 5 秒内确认。
- [ ] 同名 MQTT 通道不会覆盖 HA 状态。
- [ ] 配置文件权限为 `0600`，API 和日志不含令牌。
- [ ] 生产切换后 MQTT、CAN、工具柜和视觉扫码正常。
- [ ] 稳定 24 小时后销毁旧配置备份和所有米家凭据。
